## Правила расчета

- Навыки, окна заявок и рабочие интервалы обязательны для всех назначений.
- Согласованный принцип: выполнение заявок с учетом срочности, сокращение числа сотрудников, затем пробега.
- Предлагаемый порядок: urgent_unassigned, unassigned, used_employees, distance_km. Он дает срочным заявкам преимущество при дефиците ресурсов и еще требует подтверждения.
- Базовый алгоритм берет заявки в порядке поступления и назначает первому подходящему сотруднику по порядку входа. Заявки маршрута следуют порядку назначения.
- Истечение лимита поиска не доказывает невозможность решения.

## Получение маршрутов и статусов

- Алгоритм отправляет маршрутному API пары координат и способ передвижения сотрудника. Время отправления передается, если API его поддерживает.
- Время, расстояние и геометрия участка сохраняются в [[Назначение]]. Ответы API фиксируются в снимке [[Версия плана|версии плана]]. Время туда и обратно может различаться.
- При поддержке времени отправления участки проверяются на плановые времена. Отсутствие маршрута и ошибка API различаются, ошибка не заменяется нулевым временем.
- Поставщик API, поддержка четырех способов передвижения и геокодирование остаются открытыми вопросами.
- Источник статусов пока не выбран. Нужно определить способ получения, ключ заявки, время факта, словарь статусов и обработку повторных или запоздавших сообщений. Ручной режим для демо остается вариантом.
- Факты и история выполнения хранятся в [[Заявка|заявке]]. До выбора источника параметры webhook, опроса и доступа не детализируются.
