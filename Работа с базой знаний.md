# Работа с базой знаний

[[README|Главная]] · [[Каталог заметок]]

## Свойства заметки

YAML-блок размещается в начале файла между строками `---`. Свойства видны в Obsidian над текстом.

- `title` - название заметки.
- `type` - назначение: `navigation`, `questions`, `requirements`, `model`, `source`, `data-dictionary`, `section`, `entity`, `index`, `guide` или `note`.
- `project` - `ЛЦТ 2026`.
- `tags` - список тегов проекта и типа заметки.
- `aliases` - дополнительные названия; заполняйте только при необходимости.
- `updated` - дата последней правки заметки в формате `YYYY-MM-DD`. При содержательных изменениях обновляйте вручную. Первоначальная дата в этом наборе означает добавление общей разметки, а не согласование содержания.
- `section` - ссылка на раздел сервиса для сущности, например `"[[Разделы/Планирование]]"`.

Общие свойства не подтверждают актуальность, согласование или реализацию требований. Основания бизнес-решений указывайте в тексте заметки.

## Новая заметка

1. Создайте файл в подходящей папке и задайте имя.
2. В палитре команд (`Cmd/Ctrl+P`) выберите `Templates: Insert template`.
3. Выберите «Обычная заметка», «Описание раздела» или «Описание сущности» из папки `Шаблоны`.
4. Заполните содержание и ссылки. Для сущности укажите `section`.

Шаблоны подставляют название и дату средствами встроенного Templates. Вложения сохраняются в папку `Вложения`. Каталог исключает шаблоны и автоматически подхватывает новые заметки.

## Плагины

- [Dataview](https://github.com/blacksmithgu/obsidian-dataview), 0.5.68 - каталог по YAML-свойствам. Запросы в каталоге используют DQL.
- [Git](https://github.com/Vinzent03/obsidian-git), 2.39.0 - просмотр изменений, коммиты, получение и отправка изменений из Obsidian. На этом компьютере установлена ручная синхронизация.
- [Advanced Tables](https://github.com/tgrosinger/advanced-tables-obsidian), 0.23.2 - редактирование таблиц; сохранены существующие настройки.

Встроенные Properties, Templates, Backlinks, Outgoing links, Tags, Outline, File recovery и Bases включены. Файлы сторонних плагинов и их лицензии включены в репозиторий, чтобы сохранить используемые версии. После клонирования разрешите использование установленных сторонних плагинов при первом открытии хранилища.

## Работа с GitHub

Репозиторий: [Keberson/lct-beeline-task-2026](https://github.com/Keberson/lct-beeline-task-2026).

1. Перед началом работы выполните `Git: Pull`.
2. Отредактируйте заметки и проверьте изменения в панели Git.
3. Выполните `Git: Commit-and-sync`, чтобы создать коммит, получить удаленные изменения и отправить свои.
4. При конфликте сначала согласуйте текст и завершите слияние, затем повторите отправку.

Для нового компьютера клонируйте репозиторий через Git, затем откройте папку клона в Obsidian. Доступ к приватному репозиторию настраивается отдельно для каждого участника.

`.gitignore` исключает раскладку окон, корзину, резервные копии, локальные настройки Git и файлы окружения. Общие настройки шаблонов, свойств, таблиц, каталога хранятся вместе с заметками. Автоматические интервалы Git по умолчанию равны нулю.

## Внешние исходники

CSV из заметки [[Атрибуты исходных выгрузок]] расположены в соседней папке `Обезличивание`. PDF с ТЗ из [[Правила модели]] расположен рядом с папкой базы. Эти относительные ссылки работают в исходном локальном окружении. Для работы на другом компьютере нужны те же исходники в тех же соседних путях. Файлы не входили в указанную для публикации папку базы и в этот коммит не включены.

## Расхождения для последующего согласования

В [[Навигация сервиса]] описаны 14 сущностей, включая роль инженера, район работы, снаряжение и способ передвижения. В [[Правила модели]] перечислены 10 сущностей, которым соответствуют 10 файлов в папке `Сущности`.

Навигация и [[Потребности пользователей]] допускают требования к транспорту заявки. В [[Правила модели]] это ограничение указано как исключенное по решению пользователя. До согласования используйте точную ссылку на документ, из которого берете правило. Содержание этих заметок при технической очистке сохранено.
