# Назначение

[[Навигация сервиса]] · [[Планирование]]

Результат распределения одной заявки в одной версии плана.

## Атрибуты

| Поле | Название | Тип | Обязательность | Источник | Комментарий |
|---|---|---|---|---|---|
| **Идентификация и контекст** |  |  |  |  |  |
| `id` | ID | Строка | Да | Автоматически: система создает ID результата распределения заявки | Уникальный ключ |
| `version_id` | Версия | ID версии | Да | Автоматически: ID выполняемого расчета из Версии плана | Версия результата |
| `request_id` | Заявка | ID заявки | Да | Автоматически: ID обрабатываемой заявки из снимка входных данных | Одна заявка |
| **Результат распределения** |  |  |  |  |  |
| `status` | Результат назначения | Перечисление | Да | Автоматически: результат алгоритма: найдено назначение или заявка осталась неназначенной | assigned, unassigned |
| `employee_id` | Исполнитель | ID сотрудника | При assigned | Автоматически: алгоритм выбирает подходящего сотрудника по навыку, времени и маршруту | Пусто при unassigned |
| `route_id` | Маршрут | ID маршрута | При assigned | Автоматически: ID маршрута выбранного сотрудника в той же версии | Маршрут той же версии |
| **Обоснование результата** |  |  |  |  |  |
| `reason_code` | Причина неназначения | Перечисление | При unassigned | Автоматически: результат проверок навыка, рабочего времени и размещения заявки в маршруте | no_skill, no_work_time, time_conflict, not_found |
| `explanation` | Объяснение | Строка | Да | Автоматически: система формирует текст по выполненным проверкам и результату алгоритма | Основания назначения либо неназначения |
| `checked_skill_id` | Проверенный навык | ID навыка | Да | Автоматически: копируется `Заявка.required_skill_id` из снимка входных данных | Для объяснения |
| `incremental_distance_km` | Добавленное расстояние | Число, км | Нет | Автоматически: разница расстояния маршрута с заявкой и без нее, если алгоритм сравнивал эти варианты | Только если такой расчет выполнен |
| **Порядок и плановые сроки** |  |  |  |  |  |
| `position` | Порядок в маршруте | Целое | При assigned | Автоматически: алгоритм определяет место заявки в маршруте | Начиная с 1 |
| `arrival_at` | Прибытие | Дата и время | При assigned | Автоматически: `incoming_departure_at` плюс время пути из API |  |
| `service_start_at` | Начало работы | Дата и время | При assigned | Автоматически: алгоритм выбирает время не раньше прибытия, внутри окна заявки и рабочего интервала |  |
| `service_end_at` | Окончание работы | Дата и время | При assigned | Автоматически: `service_start_at` плюс `Заявка.duration_minutes` из снимка |  |
| `waiting_minutes` | Ожидание в рабочее время | Число, минуты | При assigned | Автоматически: рабочие минуты между `arrival_at` и `service_start_at`, без перерывов |  |
| **Путь к заявке** |  |  |  |  |  |
| `incoming_departure_at` | Отправление к заявке | Дата и время | При assigned | Автоматически: алгоритм выбирает время выхода со старта или после предыдущей работы с учетом рабочих интервалов |  |
| `incoming_travel_minutes` | Время пути | Число, минуты | При assigned | Автоматически: ответ маршрутного API для начальной и конечной точек, транспорта сотрудника и времени отправления, если оно поддерживается | Адаптер приводит единицы ответа к минутам |
| `incoming_distance_km` | Расстояние до заявки | Число, км | При assigned | Автоматически: расстояние участка из того же ответа маршрутного API | Адаптер приводит единицы ответа к километрам |
| `incoming_geometry` | Путь на карте | GeoJSON LineString | Для карты | Автоматически: геометрия участка из того же ответа маршрутного API | Пары координат: долгота, широта |
| `route_api_result_id` | Сохраненный ответ API | Строка | При assigned | Автоматически: система присваивает ID ответу маршрутного API и сохраняет его в снимке версии |  |
| **Фиксация при перепланировании** |  |  |  |  |  |
| `locked` | Зафиксировано при пересчете | Логический | При перепланировании | Автоматически: по подтвержденному состоянию работ на момент расчета | Критерии фиксации работ в пути и в процессе еще не согласованы |

## Правила

- Пара version_id + request_id уникальна. При assigned заполнены сотрудник, маршрут, порядок и плановые сроки. При unassigned эти поля пусты.
- Позиции назначений в маршруте уникальны и непрерывны. Начало работы не раньше прибытия. Следующий путь не раньше окончания предыдущей работы.
- Начало работы входит в окно заявки, вся работа и перемещения укладываются в рабочие интервалы сотрудника.
- no_skill: нет квалифицированного сотрудника. no_work_time: у подходящих по навыку сотрудников нет рабочих интервалов.
- time_conflict означает конфликт времени в проверенных вариантах. not_found означает, что алгоритм не нашел назначение, но глобальная невозможность не доказана.
- Объяснение не утверждает сравнение с альтернативой, если она не рассчитывалась.
- Критерии locked для работ в пути и в процессе еще не согласованы. Выполненные работы сохраняются в истории и не назначаются повторно.
