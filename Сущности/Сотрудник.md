# Сотрудник

[[Навигация сервиса]] · [[Сотрудники]]

Профиль пользователя, которому можно назначать выездные работы.

## Атрибуты

| Поле | Название | Тип | Обязательность | Источник | Комментарий |
|---|---|---|---|---|---|
| **Идентификация** |  |  |  |  |  |
| `id` | ID | Строка | Да | Автоматически: система создает ID при добавлении сотрудника | Уникальный ключ |
| `name` | Имя | Строка | Да | Пользователь: вводит имя в карточке сотрудника; выгрузки профилей сотрудников не предоставлены | Имя для интерфейса |
| **Оргструктура и доступность** |  |  |  |  |  |
| `department_id` | Подразделение | ID подразделения | Да | Пользователь: выбирает подразделение в карточке сотрудника | Одна текущая принадлежность |
| `active` | Участвует в планировании | Логический | Да | Пользователь: включает или исключает сотрудника из планирования | Долговременное включение профиля |
| **Квалификация** |  |  |  |  |  |
| `skill_ids` | Навыки | Список ID навыков | Да | Пользователь: выбирает навыки сотрудника из справочника | От 1 до 3 различных навыков |
| **Передвижение и точка старта** |  |  |  |  |  |
| `transport_mode` | Способ передвижения | Перечисление | Да | Пользователь: выбирает способ передвижения в карточке сотрудника | car, walking, bicycle, public_transport |
| `start_address` | Адрес старта | Строка | Условно | Пользователь: задает адрес старта; может использовать адрес офиса из метаданных импорта | Адрес или пара координат обязательны при вводе |
| `start_latitude` | Широта старта | Число | До расчета | Автоматически: геокодирование `start_address` выбранным сервисом; возможен ввод пользователем, поставщик пока не выбран | От -90 до 90 |
| `start_longitude` | Долгота старта | Число | До расчета | Автоматически: геокодирование `start_address` выбранным сервисом; возможен ввод пользователем, поставщик пока не выбран | От -180 до 180 |
| **Расчетное рабочее время на дату** |  |  |  |  |  |
| `effective_work_intervals` | Рабочие интервалы на дату | Список интервалов | Расчет | Автоматически: для выбранной даты берется `schedule_overrides`, при отсутствии записи - `Подразделение.schedule` | Каждый интервал: start_at и end_at, дата и время |
| `capacity_minutes` | Емкость дня | Целое, минуты | Расчет | Автоматически: сумма длительностей `effective_work_intervals` в минутах | Сумма длительностей интервалов |
| **Изменения рабочего дня** |  |  |  |  |  |
| `schedule_overrides` | Индивидуальные рабочие дни | Список объектов | Нет | Пользователь: добавляет изменения дня в карточке сотрудника | Каждая запись целиком заменяет график подразделения на одну дату |
| `schedule_overrides[].date` | Дата изменения | Дата YYYY-MM-DD | При изменении | Пользователь: выбирает дату в часовом поясе графика подразделения |  |
| `schedule_overrides[].intervals` | Интервалы на дату | Список объектов | При изменении | Пользователь: задает рабочие интервалы сотрудника на выбранную дату | Пустой список означает отсутствие |
| `schedule_overrides[].intervals[].start_time` | Начало интервала | Время HH:MM | Для интервала | Пользователь: вводит время начала работы |  |
| `schedule_overrides[].intervals[].end_time` | Конец интервала | Время HH:MM | Для интервала | Пользователь: вводит время окончания работы |  |
| `schedule_overrides[].reason` | Причина изменения | Строка | Нет | Пользователь: при необходимости поясняет изменение рабочего дня |  |

## Правила

- Транспорт передается маршрутному API. Отдельное требование транспорта в заявке не используется по решению пользователя.
- На дату действует не более одного индивидуального изменения. Оно целиком заменяет интервалы графика подразделения. При удалении изменения снова действует основной график.
- Изменение графика при наличии плана требует повторной проверки его выполнимости.
- Пользователь сервиса и инженер представлены одним профилем. Авторизация и роли доступа пока не определены.
- Рабочие интервалы и емкость вычисляются на выбранную дату и не являются постоянными свойствами сотрудника.
- Имя бригады из контрольного файла не создает автоматически профиль сотрудника.
