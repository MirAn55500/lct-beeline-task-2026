# Версия плана

[[Навигация сервиса]] · [[Планирование]]

Результат одного расчета с зафиксированными входами, маршрутами и метриками.

## Атрибуты

| Поле | Название | Тип | Обязательность | Источник | Комментарий |
|---|---|---|---|---|---|
| **Идентификация и история версий** |  |  |  |  |  |
| `id` | ID | Строка | Да | Автоматически: система создает ID при запуске расчета | Уникальный ключ |
| `plan_id` | План | ID плана | Да | Автоматически: ID плана, из которого пользователь запустил расчет | Родительский план |
| `number` | Номер версии | Целое | Да | Автоматически: предыдущий номер версии этого плана + 1; первая версия - 1 | Последовательный внутри плана |
| `parent_version_id` | Предыдущая версия | ID версии | Нет | Автоматически: ID исходной версии при перепланировании; пусто при первичном расчете | Для перепланирования |
| **Параметры и входные данные расчета** |  |  |  |  |  |
| `algorithm` | Алгоритм | Перечисление | Да | Пользователь: выбирает базовый или оптимизированный расчет | baseline, optimized |
| `as_of_at` | Состояние на момент | Дата и время | Да | Автоматически: система фиксирует время состояния входных данных при запуске расчета | Граница учитываемых событий |
| `request_ids` | Заявки расчета | Список ID | Да | Автоматически: сохраняется список заявок, отобранных пользователем для расчета | Включает неназначенные |
| `employee_ids` | Сотрудники расчета | Список ID | Да | Автоматически: сохраняется список сотрудников, отобранных пользователем в выбранных подразделениях | Сохраняется порядок входа |
| `input_snapshot_ref` | Снимок входных данных | Ссылка на JSON | Да | Автоматически: система сохраняет неизменяемую копию заявок, сотрудников, фактов выполнения и ответов маршрутного API | Контракт снимка описан ниже |
| `settings_snapshot` | Параметры расчета | Объект | Да | Автоматически: копируются параметры из раздела Настройки на момент запуска | Параметры расчета и сведения об использованных API на момент запуска |
| **Состояние и время расчета** |  |  |  |  |  |
| `status` | Состояние расчета | Перечисление | Да | Автоматически: система обновляет состояние по этапам выполнения расчета | calculating, ready, needs_data, failed |
| `created_at` | Начало расчета | Дата и время | Да | Автоматически: система фиксирует время запуска расчета | Время создания |
| `finished_at` | Окончание расчета | Дата и время | При завершении | Автоматически: система фиксирует время завершения или сбоя расчета | Для оценки длительности |
| `failure_reason` | Причина сбоя расчета | Строка | При failed или needs_data | Автоматически: система сохраняет ошибку расчета или перечень отсутствующих данных, выявленный перед пересчетом | Ошибка либо конкретные недостающие сведения для пересчета |
| **Результаты распределения** |  |  |  |  |  |
| `served_count` | Назначено заявок | Целое | Расчет | Автоматически: число назначений этой версии с `status=assigned` | Назначения со статусом assigned |
| `unassigned_count` | Не назначено | Целое | Расчет | Автоматически: число назначений этой версии с `status=unassigned` | Назначения со статусом unassigned |
| `urgent_unassigned_count` | Не назначено срочных | Целое | Расчет | Автоматически: число неназначенных заявок с `priority=urgent` из снимка входных данных | Срочные среди неназначенных |
| `used_employee_count` | Задействовано сотрудников | Целое | Расчет | Автоматически: число уникальных сотрудников с назначенными заявками в этой версии | Уникальные сотрудники с хотя бы одной назначенной заявкой |
| **Маршрутные метрики и проверка** |  |  |  |  |  |
| `total_distance_km` | Суммарное расстояние | Число, км | Расчет | Автоматически: сумма `Маршрут сотрудника.distance_km` этой версии | Сумма расстояний, включая путь от старта |
| `total_travel_minutes` | Время в пути | Число, минуты | Расчет | Автоматически: сумма `Маршрут сотрудника.travel_minutes` этой версии | Сумма времени перемещений |
| `constraints_valid` | Ограничения соблюдены | Логический | При ready | Автоматически: результат проверки навыков, окон заявок, рабочих интервалов и отсутствия пересечений в рассчитанном плане | Результат проверки плана |
| **Перепланирование** |  |  |  |  |  |
| `replan_reason` | Причина пересчета | Строка | При перепланировании | Пользователь: указывает причину при запуске пересчета | Например: срочная заявка, отмена заявки, недоступность сотрудника, изменение графика |
| `changed_request_ids` | Измененные назначения | Список ID заявок | При перепланировании | Автоматически: сравнение назначений с `parent_version_id`: изменился исполнитель или результат назначения |  |
| `changed_route_ids` | Измененные маршруты | Список ID маршрутов новой версии | При перепланировании | Автоматически: сравнение маршрутов по сотруднику с `parent_version_id`: изменился состав, порядок, время или путь |  |
| `removed_route_ids` | Удаленные маршруты | Список ID маршрутов прошлой версии | При перепланировании | Автоматически: маршруты из `parent_version_id`, сотрудники которых больше не задействованы |  |

## Правила

- Снимок содержит заявки, сотрудников с рабочими интервалами на дату, принятые факты выполнения до as_of_at и ответы маршрутного API.
- Каждый сохраненный ответ API содержит ID, начало и конец участка, транспорт, время отправления, время получения, статус ответа, время пути, расстояние и геометрию. При ошибке сохраняется причина.
- Готовая версия неизменяема. Изменение входов создает новую версию.
- Для baseline и optimized сравниваются одинаковые снимки входов, время состояния и ответы API.
- До расчета метрика неизвестна, а не равна нулю.
- При перепланировании новая срочная заявка сначала заполняется, затем включается в расчет. Выполненные работы остаются историей.
- Источник состояния незавершенных работ, положение сотрудников и время освобождения пока не определены. При нехватке этих сведений сохраняется needs_data с перечнем пропусков.
- В MVP достаточно одного выбранного сценария пересчета. Автоматический запуск по внешним событиям требует определения источника.
