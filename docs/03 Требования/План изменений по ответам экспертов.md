# План изменений по ответам экспертов

Подтвержденные изменения внесены в заметки базы. Ниже отделены обновленные правила от предлагаемых решений модели. Ответы от 19.09.2026 заменяют противоречащие им прежние уточнения; исходные файлы не изменяются.

## Что обновлено

| Ответы | Изменение в базе |
|---|---|
| 1, 8 | Диспетчер фиксирует завершение и отмену по информации исполнителя. Расширена трактовка отмены, описаны состояния в [[Заявка на работу]]. Закрытые исключаются из нового планирования |
| 2, 9 | Статический расчет достаточен; динамика дополнительна. Время визита можно корректировать, коммуникацию ведет поддержка. Обновлены [[Потребности пользователей]] и правила планов |
| 5, 15 | Аварийный норматив в Excel — 100 минут полного вызова. В модели обслуживание без дороги: 70 / 80 / 20 / 30. Доступность аварии — с поступления. Приоритет: авария → подключение → ремонт / дозаказ |
| 3, 10 | Навык - обязательный допуск; отсутствие исключает назначение. Характеристики допускается синтезировать, дополнительные уровни квалификации необязательны |
| 4 | Выдача оборудования в офисе на день; при пересчете нужен достаточный остаток. Размер запаса определяет команда |
| 6, 7 | В [[Глоссарий]] добавлены Beekeeper и HelpDesk; маппинг двух классификаторов и выбор навыка только по BK сохранены |
| 11, 12 | Контроль - фактический пример и ориентир численности. Для нового синтетического набора добавлена рекомендация 40/40/10/10; число исполнителей выбирает команда |
| 13, 14 | Описан условный домашний старт удаленного исполнителя. Для общественного транспорта допустима усредненная оценка; комбинированные маршруты дополнительны |

## План дальнейших изменений

Предложения ниже пока не являются решениями экспертов и не описывают реализованный код.

| Этап | Предложение | Результат |
|---|---|---|
| 1. Уточнить смысл | Закрыть вопрос об отмененных в метрике выполненных. Дорога из Excel не входит в обслуживание ни у одного вида: 70 / 80 / 20 / 30 | Однозначный completed_count. duration_minutes зафиксирован решением команды |
| 2. Статический расчет | Сравнивать планы по числу обслуженных аварий, затем подключений, затем ремонтов/дозаказов; при равенстве - меньше исполнителей, меньше времени перемещения, меньше пробега | Предлагаемый порядок критериев без произвольных весов; требует принятия командой, поскольку может уменьшить общее число заявок ради приоритетных |
| 3. Подготовка набора | Сохранить предоставленные заявки; синтезировать недостающие навыки, транспорт и исполнителей. Для отдельного нового набора использовать доли 40/40/10/10 как ориентир | Воспроизводимый набор с параметрами и seed; контрольная численность используется как ориентир |
| 4. Оборудование | При реализации учета добавить количество по каждому виду в комплект инженера и потребность заявки, считать фактический остаток после выполненных работ и резерв под оставшиеся назначения | equipment_ids остается списком видов, а новая количественная структура проверяет достаточность запаса. Стартовые количества задает команда; отмена расходует только фактически использованное оборудование |
| 5. Дополнительная динамика | Добавить историю окон и передачу изменений поддержке; пересчитывать оставшиеся работы после received_at аварии с учетом позиции, занятости и остатков | Предлагаемый сценарий: диспетчер вносит сообщенное поддержкой время, новое окно попадает в снимок плана. Правила фиксации работ в пути и в процессе выбираются отдельно |
| 6. Синхронизация схем | После выбора оставшихся решений обновить в FigJam нормативы, приоритеты, статусы, домашний старт и границу статического/динамического сценария | Схемы соответствуют актуальной базе; синхронизация FigJam выполнена при обновлении ER-модели 19.09.2026. Открытые вопросы не закрыты автоматически |

Домашний старт не отменяет выдачу оборудования в офисе. Для сценария удаленного города предлагается считать комплект уже выданным к моменту старта; логистика выдачи не включается в маршрут без отдельного решения команды.

## Проверка изменений

- Авария, поступившая в 13:00, не появляется в плане состояния на 09:00; ее выполнение не начинается до поступления и прибытия инженера.
- Исполнитель без аварийного навыка не получает аварию при любом приоритете.
- Закрытая заявка сохраняется в истории и не попадает в новый список планирования.
- Корректировка окна не меняет сохраненный старый план; информация о новом времени передается поддержке.
- При выборе количественного учета заявка не назначается, если оборудование уже израсходовано или зарезервировано под другие работы.
- Условный домашний старт находится в городе обслуживания; усредненная транспортная оценка обозначена как модельная.
