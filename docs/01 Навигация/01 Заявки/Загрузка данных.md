# Загрузка данных

Операция загрузки заявок или инженеров из файла. Пользователь выбирает файл, запускает обработку и получает число созданных и обновленных записей. Система сохраняет служебную запись загрузки для связи созданных записей с исходной выгрузкой.

## Правила

- Строка с меткой «Адрес Офиса» или «Адрес офиса» извлекается в метаданные и не считается заявкой. Адрес используется для бригады соответствующего региона. Пустые строки пропускаются. Фиксированный отступ от последней заявки не является правилом поиска офиса.
- Файлы формирует система в стандартизированном формате. Корректность структуры и записей обеспечивается при формировании файла.
- Поля «Начало» и «Окончание» задают окно прибытия в московском времени, а не длительность работы.
- Каждое непустое значение колонки «Бригада» контрольной выгрузки обозначает отдельного инженера. Повторные строки одного исполнителя сопоставляются одному профилю. Исходное значение сохраняется в source_brigade. Оно не создает бригаду сервиса. Сопоставление в рамках региона задается явно: имя не является глобальным ID.
- Для инженеров из контрольной выгрузки нужно дополнить профиль: бригада сервиса, навыки, квалификация, транспорт и график. Недостающие значения генерируются отдельно с обозначением происхождения. Контрольное распределение не ограничивает число инженеров нового расчета.
- Сопоставление колонок и справочников описано в заметке Исходные данные.
- Предлагается создавать отдельную загрузку для каждого листа XLSX. Синтетические и контрольные выгрузки остаются разными источниками, чтобы не смешивать внешние идентификаторы.

## Сценарий

1. Пользователь открывает загрузку в стакане заявок или списке инженеров и выбирает файл.
2. Система читает файл, создает новые записи и обновляет существующие.
3. Пользователь видит число созданных и обновленных записей.

Результат показывается в рамках операции. Отдельные реестр и карточка истории загрузок в текущую навигацию не входят. Связь `import_id` с технической записью сохраняется.
