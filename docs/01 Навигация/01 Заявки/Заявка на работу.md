# Заявка на работу

Выездная работа для одного инженера с адресом, окном прибытия и длительностью обслуживания.

## Атрибуты

`+` - обязательно. `-` - допускается отсутствие либо действует условие из примечания. PK - первичный ключ, FK - ссылка, UK - уникальная комбинация. Вычисляемые поля не требуют отдельного хранения. Типы и дополнительные поля являются проектом реализации на основе принятой ER-схемы.

## Связи и правила

- UK: код источника + внешний ID для импортированной заявки. Повторная загрузка обновляет запись по этой паре, но не меняет первоначальное поступление и порядок очереди.
- Заявка ссылается на общий адрес. Регион вычисляется через адрес и район и совпадает с регионом загрузки. Координаты в заявке не дублируются.
- Категория BK определяет требуемый навык через Маппинг BK с навыком. HD используется для детализации и сопоставления норматива.
- Окно ограничивает прибытие. Раннее прибытие требует ожидания, начало работы не раньше начала окна и поступления заявки. При перепланировании допускается корректировка времени визита с коммуникацией поддержки. Старый план сохраняет прежнее окно.
- Авария доступна с момента поступления, даже при окне на весь день. Рабочий норматив - 100 минут выполнения плюс отдельная дорога. Состав этих 100 минут остается открытым. Разность границ окна не является длительностью.
- Диспетчер фиксирует завершение и отмену по информации исполнителя. История и подтвержденные факты хранятся в Изменении статуса. Отсутствие обновления не означает завершение.
- Отмена означает отказ клиента или выявленную невозможность работы. Завершенные и отмененные заявки исключаются из нового планирования. Неназначение не является автоматической отменой. Считать ли отмененные выполненными в метрике - открытый вопрос.
- Исполнитель и рассчитанное расписание принадлежат конкретному плану через Назначение на заявку. Требования к транспорту и снаряжению проверяются при наличии.
- При нехватке ресурсов действует приоритет: авария → подключение → ремонт / дозаказ. Порядок сравнения общего объема и приоритетов выбирает команда.

## Список и карточка

Фильтры списка: дата окна, вид работ, приоритет, статус выполнения и результат назначения в действующем плане. Из карточки открываются назначенный инженер, позиция в маршруте и диагностика при наличии проблемы.

Неназначенные заявки появляются в блоке внимания обзора дня, срочные идут первыми. В строке: заявка, срочность, временное окно, адрес, вид работ и причина неназначения. Действия: открыть заявку, подобрать исполнителя, запустить пересчет.

## Статусы

Завершение и отмену вносит диспетчер по информации исполнителя. Принятые статусы и факты сохраняются в [[Изменение статуса]]. Внутренние коды являются проектом реализации.

| Исходное состояние | Рабочая интерпретация |
|---|---|
| Не отправлена / Отправлена | Ожидает выполнения, pending |
| В пути | Инженер направляется к адресу, en_route |
| В работе | Выполняется, in_progress |
| Выполнена | Подтвержденное завершение, completed |
| Отменена | Отказ клиента или невозможность работы, cancelled |
| Просрочена | Исходная отметка сохранена. Итоговое состояние требует уточнения |
| Нет подтвержденного состояния | unknown |

Завершенные и отмененные исключаются из нового планирования. Отмена не считается выполненной работой до уточнения метрики. При первоначальном расчете последующие факты контрольного файла не подмешиваются во входы.
