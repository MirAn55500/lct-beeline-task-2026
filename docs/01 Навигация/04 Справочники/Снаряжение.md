# Снаряжение

Оборудование для выполнения заявки: роутер или приставка. Потребность задается у заявки и не зависит от типа подключения. Стартовый комплект инженера выдается в начале дня.

## Атрибуты

| Наименование параметра | Название | Описание параметра | Тип данных | Обязательность | Пример заполнения | Примечание | Комментарий |
|---|---|---|---|---|---|---|---|
| **Основные сведения** |  |  |  |  |  |  |  |
| `id` | ID | Автоматически: уникальный ключ вида оборудования | Идентификатор | + | router | Уникальный ключ | PK: первичный ключ |
| `name` | Название | Название вида оборудования | Строка | + | Роутер | Подтверждены роутер и приставка |  |
| `description` | Описание | Назначение оборудования | Строка | - | Оборудование для установки у клиента |  |  |
| **Классификация** |  |  |  |  |  |  |  |
| `code` | Код оборудования | При подготовке набора: код подтвержденного вида оборудования | Строка | + | router | Предлагаемые коды: router, set_top_box |  |
| **Доступность** |  |  |  |  |  |  |  |
| `active` | Доступно для выбора | Пользователь: разрешает выбор записи в новых карточках | Логический | + | true | Предложение; отключение не удаляет исторические связи |  |

## Правила

- В заявке указывается, требуется ли оборудование и какой вид. Пустой список означает, что оборудование не требуется.
- Потребность не выводится из FMC/FTTB или признака гигабитного подключения.
- Доступность определяется стартовым комплектом инженера на дату плана, а не ролью. Базовая выдача происходит в начале дня.
- Количество экземпляров, расход при установке и допустимость обоих видов на одной заявке требуют уточнения. Модель наличия вида не доказывает достаточность одного экземпляра для нескольких установок.
- Учет оборудования сохраняется дополнительной возможностью прототипа. Отдельный складской процесс не задан.
