# План работы

Версия расчета назначений и маршрутов на один день.

## Атрибуты

`+` - обязательно. `-` - допускается отсутствие либо действует условие из примечания. PK - первичный ключ, FK - ссылка, UK - уникальная комбинация. Вычисляемые поля не требуют отдельного хранения. Типы и дополнительные поля являются проектом реализации на основе принятой ER-схемы.

## Связи и правила

- Каждый запуск расчета создает новый plan_id. reference_plan ссылается на предыдущую версию, version - номер внутри цепочки. Циклы запрещены, версия дочернего плана равна версии родителя + 1.
- Статус плана отделен от состояния расчета. После фиксации входы и результаты не перезаписываются, жизненный статус может изменяться.
- Снэпшот загрузки фиксирует происхождение файла. Неизменяемый снимок входов плана фиксирует состояние для конкретного расчета и не заменяется ссылками на текущие записи.
- Входы содержат выбранные заявки и инженеров в порядке входа, территории, адреса по одному экземпляру на ID, офисы бригад, графики, навыки и уровни, комплект на дату, нормы и факты до as_of_at. Настройки и ответы маршрутного API фиксируются с расчетом.
- Дневной маршрут инженера вычисляется по паре план + инженер из назначений и участков пути. Маршрут не имеет второй независимой связи с планом.
- До подтверждения новой версии действует предыдущая. Применение нового и архивирование прежнего плана выполняются одной операцией. Для совпадающей области и даты действует один план.
- Назначение не доказывает выполнение. Прогноз и фактические показатели считаются раздельно. Базовый и оптимизированный варианты сравниваются на одинаковых входах.
- Начатые работы, текущее положение инженеров и правила фиксации уточняются в Открытых вопросах. Недостаток необходимых входов дает needs_data, а не вымышленный маршрут.
- Обязателен статический расчет одного дня. Динамическое перепланирование - дополнительный сценарий. Новая авария появляется только после received_at, закрытые работы не назначаются заново.

## Жизненный цикл

- Новый план создается как `draft` с расчетом `not_started`.
- При запуске фиксируются входные данные и параметры; расчет переходит в `calculating`, затем в `ready`, `needs_data` или `failed`. Ошибка расчета не меняет действующий план.
- План с `calculation_status=ready` и соблюденными ограничениями можно передать на согласование: `draft → pending_approval`.
- При подтверждении `pending_approval → active`. До этого продолжает действовать прежний план.
- Подтверждение нового плана и перевод заменяемого действующего плана в `archived` выполняются одной операцией. Первый план применяется без предшественника.
- Отклоненный или ненужный черновик можно перевести в `cancelled`. Завершенный действующий план можно перевести в `archived`.
- Для одной области планирования на дату действует один план. Новый вариант, ссылающийся на уже замененный план, перед применением требует проверки относительно актуального действующего плана.


## Показатели и сравнение

Показатели являются проекциями результата. Для исторического сравнения используются сохраненные входы и состояние фактов на выбранный момент.

| Показатель | Правило |
|---|---|
| Назначено | Число назначений со статусом assigned |
| Выполнимо | Число назначений, прошедших проверку всех ограничений |
| Выполнено | Число заявок с подтвержденным завершением на выбранный момент |
| Не назначено | Число назначений со статусом unassigned |
| Аварийных не назначено | Неназначенные аварийные заявки |
| Задействовано инженеров | Число различных инженеров успешных назначений |
| Время пути и расстояние | Сумма участков маршрутов выбранного плана |
| Ограничения соблюдены | Итог проверки расписания, регионов, навыков, транспорта и снаряжения |
| Изменения относительно предыдущего | Сравнение исполнителя, позиции и сроков по заявке, состава маршрутов по инженеру |

До расчета показатели неизвестны, а не равны нулю. Подробные критерии - в [[Правила модели]].
