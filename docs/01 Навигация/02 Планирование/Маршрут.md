# Маршрут

Один входящий участок пути к назначению, как в исходной ER-схеме.

## Атрибуты

`+` - обязательно. `-` - допускается отсутствие либо действует условие из примечания. PK - первичный ключ, FK - ссылка, UK - уникальная комбинация. Вычисляемые поля не требуют отдельного хранения. Типы и дополнительные поля являются проектом реализации на основе принятой ER-схемы.

## Связи и правила

- UK: assignment_id. У назначенной заявки один входящий участок, у неназначенной его нет. Полный дневной маршрут получается по плану, инженеру и позиции назначения.
- Первый участок первоначального плана идет из условного домашнего адреса инженера, если он задан, иначе из офиса бригады. Следующий начинается у предыдущей заявки. Возврат не требуется.
- Конечная точка совпадает с адресом заявки. Обычно начальная точка тоже адрес. При пересчете из текущего положения start_point может быть пустым, а координаты старта задаются явно.
- start_latitude/start_longitude используются только при отсутствии start_point и требуют подтвержденной текущей позиции. Для обычного адреса координаты читаются из снимка входов плана. Произвольная точка не создает фиктивный адрес.
- Время окончания участка равно рассчитанному прибытию назначения. Оценка перемещения включает сопутствующие затраты, геометрия описывает путь.
- Транспорт вычисляется из назначения, активность - из статуса связанного плана. Отдельное переключение активности участка не допускается.
- Изменение адреса или новый ответ API не меняют исторический маршрут. Используются сохраненные адреса и ответ API расчета.
