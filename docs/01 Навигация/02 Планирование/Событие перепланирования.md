# Событие перепланирования

Изменение входных условий, учтенное при пересчете плана.

## Атрибуты

`+` - обязательно. `-` - допускается отсутствие либо действует условие из примечания. PK - первичный ключ, FK - ссылка, UK - уникальная комбинация. Вычисляемые поля не требуют отдельного хранения. Типы и дополнительные поля являются проектом реализации на основе принятой ER-схемы.

| Наименование параметра | Название | Описание параметра | Тип данных | Обязательность | Пример заполнения | Примечание |
|---|---|---|---|---|---|---|
| `event_id` | Идентификатор | Автоматически: уникальный ключ записи | Идентификатор | + | replan_event-001 | PK. Обязательность ключа принята в модели |
| `event_type` | Тип события | Автоматически или пользователь: ссылка на связанную запись | Идентификатор | + | dict-001 | FK: [[Словарное значение]].dict_id. Группа словаря: `replan_event_type` |
| `event_time` | Время события | Источник или пользователь: время изменения входов | Дата и время | + | 2026-08-17T12:00:00+03:00 |  |
| `request` | Заявка | Автоматически или пользователь: ссылка на связанную запись | Идентификатор | - | request-001 | FK: [[Заявка на работу]].request_id |

## Связи и правила

- Тип события определяет обязательный контекст: новая или измененная заявка, статус выполнения либо изменение доступности инженера. Состав типов является проектом модели.
- Несколько событий могут быть учтены одним новым планом. Связь result_plan заполняется после успешного расчета. Без результата она пустая.
- Повторные попытки расчета создают новые планы. Событие связывается с успешным результатом, не размножая бизнес-событие. Неудачные попытки доступны по цепочке планов и состояниям расчета.
- Изменение статуса связывается с записью истории. Диспетчер фиксирует завершение и отмену. Динамика дополнительна, способ автоматического запуска и текущая позиция выбираются командой.
