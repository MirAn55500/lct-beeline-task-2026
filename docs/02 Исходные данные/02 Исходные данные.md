# Исходные данные

Источник: [Выгрузки.xlsx](../../../Наборы%20данных/Выгрузки.xlsx). Три территории, по две выгрузки: синтетические заявки и контрольное распределение. Атрибуты, примеры ячеек, число заявок и адреса офисов приведены в заметках территорий.

## Выгрузки

- [[Восток|Восток]]
- [[Юго-восток|Юго-восток]]
- [[Югоцентр|Югоцентр]]

Рабочие восстановленные CSV находятся рядом с базой, в папке `Наборы данных/Датасеты (восстановленные)`. Кодировка UTF-8 с BOM, разделитель `;`. Пустые значения подсчитаны только по заявкам, без служебных строк и адресов офисов. Синтетические и контрольные записи считаются отдельно.

## Нормативы работ

[[Нормативы работ]] - оптимальное время инженера на один вызов для четырех категорий работ. Базовый норматив включает дорогу до клиента/ТКД, технические работы и оформление документов. Исходный файл сохранен вместе с наборами данных.

## Значения категорий

Общий перечень фактически встречающихся значений во всех шести выгрузках. Это не утвержденные справочники сервиса.

Категории Beekeeper и типы заявок HelpDesk приведены вместе в [[Маппинг типов заявок]]. Соответствие BK навыкам из ТЗ - в [[Навык]].

## Ограничения переноса

- Координаты, длительность работы, приоритет, требуемый навык, транспорт и рабочее время сотрудников отдельными полями в исходных выгрузках заявок не представлены. Нормативы времени получены отдельным файлом, см. [[Нормативы работ]].
- Колонка «Бригада» контрольного распределения обозначает одного инженера. Повторения одного исполнителя сопоставляются одному профилю в рамках региона. Это не сущность «Бригада» сервиса; сопоставление задается отдельно.
- Поля BK и HD относятся к классификаторам Beekeeper и HelpDesk одной заявки. Исходные значения сохранены. Маппинг навыков задан в [[Навык]], статусов - в [[Заявка на работу#Статусы]].

## Что дополнить

Правила подготовки дополнительного набора. Исходные CSV/XLSX сохраняются без изменений. Отсутствующие свойства не выдаются за сведения организатора.

| Данные | Правило подготовки |
|---|---|
| Бригады сервиса | Регион, офис старта из служебной строки, график и расчетная продолжительность рабочего дня. Состав инженеров задается отдельно от исходной колонки «Бригада» |
| Профили инженеров | ID, имя, бригада, навыки, транспорт и оборудование на день; дополнительные уровни квалификации необязательны. Каждый исполнитель выполняет заявку один |
| Навыки и квалификация | Команда задает допуски к типам работ; отсутствие навыка запрещает назначение. Дополнительные уровни можно синтезировать при выборе этой модели |
| Транспорт | Синтетические доли с преобладанием пеших инженеров и пользователей общественного транспорта. Точные проценты фиксируются в параметрах набора. Транспорт независим от навыков |
| Виды работ | Навык определяется только по BK по таблице в заметке Навык. Сопоставление BK/HD категориям нормативов уточняется. Обслуживание включает технические работы и документы, перемещение считается отдельно |
| Оборудование | Выдача в офисе на весь день. Команда определяет запас и расход; при пересчете учитывается остаток, а не повторная выдача полного комплекта |
| География | Соответствие районов регионам. Для удаленных городов допускается условный домашний старт; фактические GPS-координаты не нужны. Геокодирование - предпочтительно открытое ПО |
| Время перемещения | По способу передвижения с сопутствующими затратами. Для общественного транспорта допустимы усредненная скорость или время; реалистичные комбинированные маршруты дополнительны |
| Воспроизводимость | Параметры и seed генерации сохраняются вместе с набором; исходные, синтетические и вычисленные значения различимы |

Набор заявок относится к одному дню, время московское. Окончание минус начало не используется как длительность работы. При отсутствии времени поступления порядок строк можно принять за порядок базового алгоритма, явно отметив это допущение.

Если команда добавляет динамический сценарий, поступление аварии задается отдельным событием с received_at. Будущие статусы и события не подмешиваются в более ранний снимок.

## Сравнение

По ответам экспертов контрольная выборка отражает фактическую работу за один день, синтетическая - очищенный набор для собственного распределения. Число исполнителей контрольной выборки можно использовать как ориентир; команда вправе выбрать другое. Контроль не является эталоном качества. Базовый алгоритм и оптимизированный сравниваются на одних входах.

Контрольные файлы используются для дополнительного сравнения после сопоставления заявок. Совпадение строк по позиции не является устойчивым ключом. Число назначений, прогноз выполнимости и фактическое выполнение различаются.

## Генерация и календарная дата

При самостоятельной генерации заявок эксперты рекомендуют ориентир: 40% локальных, 40% подключений, 10% аварий и 10% дозаказов. Это рекомендация для нового синтетического набора; предоставленные выгрузки под эти доли не изменяются.

Эксперты называют контроль реальным днем сентября в Москве. В предоставленных файлах встречается дата 17.08.2026. Исходные даты сохранены; расхождение календарного месяца вынесено в [[Открытые вопросы]].
