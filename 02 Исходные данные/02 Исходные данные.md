# Исходные данные

Источник: [Выгрузки.xlsx](../../Наборы%20данных/Выгрузки.xlsx). Три территории, по две выгрузки: синтетические заявки и контрольное распределение. Атрибуты, примеры ячеек, число заявок и адреса офисов приведены в заметках территорий.

## Выгрузки

- [[Восток|Восток]]
- [[Юго-восток|Юго-восток]]
- [[Югоцентр|Югоцентр]]

Исходные CSV находятся рядом с базой, в папке `Обезличивание`. Кодировка UTF-8 с BOM, разделитель `;`. Пустые значения подсчитаны только по заявкам, без служебных строк и адресов офисов. Синтетические и контрольные записи считаются отдельно.

## Значения категорий

Общий перечень фактически встречающихся значений во всех шести выгрузках. Это не утвержденные справочники сервиса.

### Тип заявки BK

- Глобальная проблема.
- Дозаказ.
- Локальная заявка.
- Подключение.

### Тип заявки HD

- IP-адрес 169....
- TVE/ENT. Другие ошибки.
- TVE/ENT. Замена приставки техником.
- Авария.
- Дозаказ оборудования.
- Заказ подключения/Дозаказ оборудования.
- Заявка на подключение.
- Информация.
- Конвергенция абонента.
- Мониторинг.
- Нет линка.
- Низкая скорость.
- Переключение на Гбит/с.
- Работа с кабелем.
- Разрывы.
- Рост ошибок на порту.
- Роутер. Замена техническим специалистом.
- ТВ. Замена приставки техником.

### Статус BK

- В пути.
- В работе.
- Выполнена.
- Не отправлена.
- Отменена.
- Отправлена.
- Просрочена.

### Подключение

- FMC.

## Ограничения переноса

- Координаты, длительность работы, приоритет, требуемый навык, транспорт и рабочее время сотрудников отдельными полями в этих файлах не представлены.
- Контрольное назначение хранит имя, но не идентификатор сотрудника сервиса. Для сопоставления нужен справочник.
- Типы и статусы источника сохранены как исходные значения. Их соответствие правилам планирования нужно задать отдельно.

## Что дополнить

- Справочник сотрудников: ID, имя, подразделение, навыки, транспорт, точка старта.
- График подразделения и индивидуальные изменения в карточках сотрудников.
- Сопоставление типов работ, требуемый навык, длительность и приоритет каждой заявки.
- Координаты адресов и время перемещений из API.
- Изменение входных данных и причина пересчета для демонстрации перепланирования.

Окончание минус начало не используется как длительность работы. При отсутствии времени поступления порядок строк можно принять за порядок заявок базового алгоритма, явно отметив это допущение в наборе.

## Сравнение

Базовый алгоритм строится по правилу ТЗ на тех же входах, что и оптимизированный. Контрольные файлы можно использовать как дополнительное сравнение после установления соответствия заявок. Совпадение строк по позиции само по себе не является устойчивым ключом.
