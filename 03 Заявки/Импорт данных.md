# Импорт данных

Загрузка заявок или инженеров из файла с результатами обработки и ошибками. Сохраняет связь записей с исходной выгрузкой.

Состав полей и обязательность - проект модели. Примеры отдельных полей условные и не образуют одну запись. `+` - обязательно; `-` - необязательно или требуется при условии из примечания.

|---|---|---|---|---|---|---|---|
| `id` | ID | При импорте: система создает ID загрузки при выборе файла | Идентификатор | + | import-001 | Уникальный ключ; обязательность ключа принята в проекте модели |  |
| `source_key` | Код источника | Пользователь: выбирает код набора перед импортом; синтетические и контрольные наборы разделяются | Строка | + | east_synthetic | Разделяет внешние ключи |  |
| `entity_type` | Тип записей | Пользователь: выбирает загрузку заявок или профилей инженеров | Перечисление | + | request | Предложение значений: request, engineer; данные профилей пока не предоставлены |  |

## Правила

- Строка Адрес Офиса / Адрес офиса извлекается в метаданные. Пустые строки пропускаются.
- Ошибочные заявки не передаются оптимизатору. Они отображаются как ошибки импорта, отдельно от неназначенных заявок.
- Поле Начало/Окончание из CSV предлагается трактовать как границы окна. Значение требует подтверждения владельца данных.
- Бригада из контрольного CSV является исходным назначением, а не полным профилем сотрудника.
- Нормативы работ, навыки, приоритеты и профили сотрудников нужно дополнить до планирования.
- Сопоставление колонок и справочников описано в заметке Исходные данные.
- Предлагается создавать отдельный импорт для каждого листа XLSX. Синтетические и контрольные выгрузки остаются разными источниками, чтобы не смешивать внешние идентификаторы.
